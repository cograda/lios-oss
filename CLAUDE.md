# lios core — Operating Manual

Formerly **Comar**, Co-Managed Archive, from the Irish *comar* (confluence, meeting place) — the platform took the lios name on 2026-09-02; the house is still called Comar.

Unified family knowledge system. Client-server architecture with three components: the Obsidian vault (knowledge layer), a remote server (data engine + canonical MCP), and a local client daemon that runs as a side-car for things that physically need to happen on the Mac (EventKit + vault file watcher).

## Architecture

```
Claude Code ── MCP / Streamable HTTP ── comar-server (8400/mcp/, per-user bearer)
                                              │
                                              │ tools (see core/STATE.md, generated — annotated read/write/destructive)
                                              │   • vault_search / vault_recent / vault_stats
                                              │   • reminders_add / complete / update
                                              │     └─ server enqueues → SSE callback to daemon → EventKit
                                              │   • calendar / mail / finance / health / weather / …
                                              ▼
                                  Postgres 16 + pgvector

lios-sync (daemon, localhost:9400) — pure side-car; GET /health only
  ├── Vault watcher: fsevents → POST /api/v1/vault/push (re-embed)
  ├── Reminders: subscribes to server SSE callbacks → executes EventKit (PyObjC)
  └── /api/v1/heartbeat for client liveness

Vault file edits in Claude Code use the native filesystem tools (Read / Edit /
Write / Grep) against the vault path on disk. The daemon's watcher picks up
the change and pushes it to the server for re-indexing.
```

**Key properties:**
- One MCP endpoint, one transport: **Streamable HTTP** at `/mcp/`, per-user bearer auth (post `bd65c42`). Claude Code's `.mcp.json` points directly at the server. The daemon's legacy localhost MCP proxy was retired in Phase 4 (2026-07-14) — a canary (started 2026-07-10) logged zero non-health traffic in 4 days, confirming nothing used it. The daemon's local port now serves `GET /health` only.
- The daemon exists for three macOS-only jobs: **EventKit** (Apple Reminders write-back), **fsevents** (vault file change push), and — since 2026-07-31, opt-in — **Voice Memos capture** (watches the `group.com.apple.VoiceMemos.shared` container, which only a local process with Full Disk Access can read, and uploads raw bytes to `/api/inbox/ingest`). All three are things that physically must happen locally; the voice-memo watcher deliberately does no parsing, holds no OpenAI key and makes no decisions — transcription is the server's `transcription` integration.
- Tool/integration counts: **see `core/STATE.md`** (generated by `scripts/state_of_project.py`, `make -C core state-of-project`; CI fails on drift — S5.2). This line used to state a number by hand and had drifted wrong four times running (119 → 126 → 129/130 → 134, each one "measured" and each superseded within days) — the exact failure "MCP tools: measure, never quote" already named. A rendered field can't drift silently; a typed one always will. Every tool carries MCP `annotations` (readOnlyHint / destructiveHint / idempotentHint / openWorldHint).
- Single instructions block (`server/backend/app/mcp/instructions.py`) is what the model sees on connect.
- Audio transcription lives in a separate repo (`cograda/scribe`) — lios-sync is single-purpose.

## Platform vs personalisation

The repo is meant to be publishable; household-specific values are not code.
Anything that names a person, a contractor, a project, or a location belongs in
the `integration_config` table (edit via `PUT /api/integrations/{name}/config`)
or its `HOME_*` env fallback — never in a committed default.

`tests/test_personalisation_guard.py` enforces this in CI: it sweeps every MCP
tool name, description and input schema plus every manifest config default for
household names, project names and private IPs. **If it fails, the fix is a
config key, not an allowlist entry.**

Extracted: corpus default project tag; snag trades, trade labels and room
aliases; weather location; Irish Rail station; the whole commute route
(`commute/routing.py` — `domain.py` stays pure, and a test enforces that). The
MCP tool `riverside_context` was renamed `corpus_search` for the same reason — a
tool name is public API.

Two rules learned the hard way here:

1. **Config controls what is *offered*, never what is *rejected retroactively*.**
   Validation sets must union config with what's already in the table
   (`snags/vocab.py::allowed_trades`), or narrowing a config key silently makes
   existing rows un-editable.
2. **`required` config is not a fit when read paths still work.** It gates the
   whole integration off via `is_configured()`. Prefer failing at the one call
   site that needs the value, with a `PermanentError` naming the missing keys —
   the scheduler records that on SyncState and it surfaces on the dashboard.

Remaining, deliberately: the `.md.j2` prompt templates carry worked examples
naming family members (concrete examples make better prompts — treat them as a
content layer). And the commute solver still assumes one bus leg plus one rail
leg meeting at a single interchange; a different journey shape is a rewrite,
not a config key.

- **vault/** is gitignored. Syncs to server via Google Drive + rclone.
- **client/** is the local daemon — install with `pipx install lios-sync`.
- **server/** deploys to `SERVER_IP` via Docker. See `server/CLAUDE.md` for server-specific docs.
- **scribe** (audio transcription) lives in a separate repo at `Code/scribe/` — drops markdown into a watched folder.

## New Machine Setup

Per-machine config lives outside the repo (token, vault path, server URL). The repo carries the **spec** (`client/config.example.toml`) and the **bootstrap script** (`scripts/setup-machine.sh`).

```bash
git clone git@github.com:cograda/comar.git
cd comar
bash scripts/setup-machine.sh
# → prompts for user (alex/sam), server URL, bearer token
# → installs the daemon via pipx
# → writes ~/.config/lios/config.toml
# → writes ~/.config/lios/env.sh and patches ~/.zshenv to source it
# → verifies with a server heartbeat
# Quit and relaunch Claude Code afterwards so it picks up COMAR_TOKEN.
```

**Why `~/.zshenv` and not `~/.zshrc`:** Claude Code expands `${COMAR_TOKEN}` in `.mcp.json` from its own process environment at startup. When launched from Spotlight/Dock/an IDE, zsh runs `~/.zshenv` but **not** `~/.zshrc` — so token exports in `.zshrc` are invisible to GUI-launched apps. Putting the source line in `~/.zshenv` is the fix.

**Single source of truth:** the per-user bearer token lives only in `~/.config/lios/config.toml` (used by the daemon). `~/.config/lios/env.sh` reads it from there and exports `COMAR_TOKEN` for `.mcp.json` consumers. Don't paste tokens into `.zshrc`/`.zshenv` directly.

**Per-machine vs portable:**

| Bit | Where | In git? |
|---|---|---|
| `.mcp.json` (uses `${COMAR_TOKEN}`) | repo | yes |
| Daemon config schema | `client/config.example.toml` | yes |
| Bootstrap orchestrator | `scripts/setup-machine.sh` | yes |
| Real config (with token + vault path) | `~/.config/lios/config.toml` | no |
| Env shim | `~/.config/lios/env.sh` | no |
| `.zshenv` source line | `~/.zshenv` | no |

If MCP isn't connecting in a Claude Code session, check (in order): `echo $COMAR_TOKEN` is non-empty in the *exact* shell that launched Claude Code; `curl -H "Authorization: Bearer $COMAR_TOKEN" $SERVER_URL/api/v1/heartbeat` returns 200; you're on home Wi-Fi or Tailscale is up.

**Which address to use where.** The three consumers reach the server differently, because only one of them can choose at runtime:

| Consumer | Address | Why |
|---|---|---|
| lios-sync daemon | `server.urls` — an *ordered list*, LAN then tailnet | Probes each with an authenticated heartbeat and uses the first that answers; re-resolves on every reconnect and drifts back to LAN when home. See `client/src/lios_sync/endpoints.py`. |
| Claude Code `.mcp.json` | tailnet URL only | MCP config is a static string with no fallback, so it has to be the address that resolves everywhere. Costs a WireGuard hop at home; breaks only if Tailscale is off on the Mac. |
| Health Auto Export (iOS) | tailnet URL only | Third-party app, one URL field. Requires Tailscale stay on on the phone. |

The probe is authenticated (`/api/v1/heartbeat` must return 200 *and* JSON) rather than a plain reachability check — `192.168.1.x` is common enough that a foreign network's router or printer will answer on the configured LAN address, and binding to it fails every subsequent request confusingly instead of falling through. `lios-sync status` prints every candidate and its reachability, so "LAN is down and I silently fell back to Tailscale" is visible rather than inferred.

## Tasks — routines and rounds (chunk E3, 2026-09-03)

`app/integrations/tasks/` is the task and project ledger (DB is source of
truth; `Task Backlog.md` is a generated one-way view). Vocabulary ruled by
Alex, do not re-open: a **loop** is anything with a definition of done; a
**routine** is a recurring loop template that never closes itself; a
**round** is one occurrence of a routine, and it closes. **A round IS a
`tasks` row** (`Task.routine_id` set) — no separate occurrence table, so
rounds get every existing lens/queue/block/comment/history/transfer for
free. Only the *next* round exists as an open row (just-in-time minting):
an interval routine mints on completion, a fixed/window routine mints on
the 15-minute scheduler tick (`routines.run_tick`), and a round still open
when the next is due is closed `dropped` with a `skipped` event before the
next is minted. See `app/integrations/tasks/README.md` and
`routines.py`'s module docstring for the full policy, the window-kind
stopgap, and why rounds are excluded from `tasks_review`, duplicate
detection, and the per-domain render sections.

⚠️ **`Task Backlog.md` is strictly one-way and write-only — the render never
refuses (2026-09-14).** It used to detect a hand edit since the
last render and refuse to regenerate unless called with `force=True`. On
2026-09-14 one stray hand edit caused six `tasks_add` calls in a row to
report a skipped render — the ledger and the file drifting apart, which is
the exact failure the guard was meant to prevent. Ruling: the Loops app
(`apps/loops`) is the human-facing surface; the markdown exists for Obsidian
search/backlinks only, and must never block a write or hold state. Every
render (`write_backlog_note` in `app/integrations/tasks/render.py`)
overwrites the file unconditionally now; the file's own frontmatter carries
a banner saying so. `check_drift`, `force`, and `render_skipped`/
`render_error` on every `tasks_*` tool are gone, not deprecated. See
`server/CLAUDE.md`'s Known Issues for the full account.

⚠️ **The two readers this left alone are now also gone (2026-09-15).** The
ledger became the tasks system's sole source of truth: nothing may consume
`Task Backlog.md` as input any more. `apple_reminders/backlog_sync.py` (the
pre-ledger two-way EventKit sync, plus its `reminders_sync_backlog` MCP
tool, `POST /api/reminders/backlog-sync` route, and the
`reminders_push_vault_to_reminders` config key) is deleted outright —
superseded by `tasks/reminders_inlet.py`'s explicit `linked_task_uid` link,
which already existed and already ran on a tighter cadence (15 min vs 30).
The reactive trigger on `/api/v1/reminders/push` now fires
`reminders_inlet.tick_once` instead of `sync_backlogs`
(`app/api/v1.py::_trigger_reminders_inlet`). `core/scripts/taskgraph_parse.py`
(and its sole consumer, `taskgraph_compare.py`) is deleted too — the parked
LLM-edge-inference prototype. The one-off `Task Backlog.md` importer
(`app/integrations/tasks/importer.py` + `parse.py`) went the same day:
Alex's ruling was "we can always batch import through Claude"
(`tasks_add` calls); the three `*_import` values stay in `TASK_SOURCES`
(`models.py`) for existing rows, not because anything writes them now. The
markdown-parsing logic all three depended on survives only as a test
fixture (`core/server/backend/tests/legacy_backlog_{parse,importer}.py`) —
not imported by any `app/` code, not reachable via any tool or route.

## `/kickoff`'s Synthesise phase — the TriageList (2026-09-10, lios#192/#193)

`/kickoff`'s Track C (`app/prompts/templates/kickoff.md.j2`) no longer scores
individual WhatsApp/Gmail messages in isolation, and the old per-message
intake table plus Track C2's tiered Email/WhatsApp digests are both retired.
Track C now builds a two-list **TriageList**: List 1 is `inbox_pending`'s
explicit captures (unchanged); List 2 is `conversations_since` (added in the
prior step, `app/integrations/system/conversations.py`) grouped by chat/
thread, each labelled **FYI** or **DECIDE** by a cheap Haiku judgement call —
never a per-message scan. `tasks_intake_candidates()` is used only to tag a
conversation group as already-in-the-ledger (FYI), never presented as its
own list. The note's `## Conversations` section replaces `## Email`/
`## WhatsApp`, rendered from List 2. `/checkin`'s (`/refresh` until
2026-09-10) `email`/`whatsapp` filters now repoint at the same TriageList rerun rather than a separate Track C2
pass. Full design: the comar vault's `Projects/lios/Plans/Daily Kickoff —
Phase contract (design, 2026-09-10).md` (§4, §7). Per-row skip persistence
(re-ask-once-then-drop) is deferred to the next build step, noted inline in
the templates.
